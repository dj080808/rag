# 🛠️ Almagrag — DevOps 智能排障助手

基于 **Qdrant 向量数据库 + 通义千问** 的运维故障知识库系统。支持语义检索、结构化录入，以及 RRF 混合检索、标签过滤、LLM 重排序、HyDE 假设文档等多重检索优化策略。

## 功能概览

| 功能 | 说明 |
|------|------|
| 🔍 故障智能检索 | 支持口语化/技术化查询，返回知识库中最匹配的历史排障案例 |
| ✍️ 维护日志录入 | 结构化表单录入，自动生成技术标签，长文本智能摘要脱水 |
| 💬 上下文连续检索 | 携带对话历史，每次检索叠加上下文，逐步逼近目标 |
| 🆕 全新独立检索 | 每次检索完全独立，不关联历史 |
| ⚙️ 多重检索优化 | RRF、HyDE、标签过滤、LLM 重排序、查询扩展等 |

## 技术架构

```
用户查询
  │
  ├─ 上下文改写 (历史对话融合)
  ├─ HyDE 假设文档 (可选，口语→技术术语)
  ├─ 标签提取 (LLM 生成查询标签)
  │
  ├─ RRF 混合检索 ─────────────────────┐
  │   ├─ 稠密向量 (semantic, 1024-dim)  │
  │   └─ 稀疏向量 (lexical, n-gram)     │→ 融合排序
  │                                      │
  ├─ 标签过滤 + 错误码 must 过滤 ───────┘
  ├─ LLM 重排序 (精选 Top-N)
  │
  └─ LLM 合成诊断报告 (严格防幻觉，仅基于检索结果)
```

## 快速开始

### 环境要求

- Python 3.10+
- Qdrant 向量数据库 (本地运行)
- 阿里云 DashScope API Key

### 安装

```bash
# 1. 克隆项目
git clone <repo-url>
cd almagrag

# 2. 安装依赖
pip install -r requirements.txt

# 3. 设置 API Key
# 方式 A: 环境变量
export DASHSCOPE_API_KEY="sk-xxxxxxxxxxxx"

# 方式 B: 在 app.py 中取消注释第 25 行并填入 Key
# os.environ["DASHSCOPE_API_KEY"] = "sk-xxxxxxxxxxxx"

# 4. 启动 Qdrant (如未运行)
docker run -p 6333:6333 qdrant/qdrant

# 5. 启动应用
streamlit run app.py
```

### 使用流程

1. **录入知识** → 侧边栏选择「✍️ 维护日志智能录入」→ 填写故障单表单 → 提交
2. **检索知识** → 侧边栏选择「🔍 故障智能检索」→ 输入问题 → 查看诊断报告
3. **优化检索** → 侧边栏展开「🔧 高级检索选项」→ 按需开启 HyDE / 查询扩展 / RRF

## 检索优化策略

| 策略 | 默认 | 说明 |
|------|------|------|
| **RRF 混合检索** | ✅ | 稠密向量（语义）+ 稀疏 n-gram 向量（词法）融合排序 |
| **标签过滤** | ✅ | 从查询中提取技术标签，仅搜索匹配标签的案例，结果不足时自动回退 |
| **LLM 重排序** | ✅ | 向量检索返回候选后，由 LLM 按相关性精排 |
| **分数阈值** | 0.45 | 过滤低相似度结果 |
| **错误码 must 过滤** | 自动 | 完整类名（如 `io.lettuce.core.RedisChannelHandler`）精确匹配 |
| **HyDE 假设文档** | 关闭 | LLM 先生成假设排障记录，再以其嵌入进行检索（口语查询大幅提升精确率） |
| **查询扩展** | 关闭 | 生成语义等价变体，提升召回率 |
| **嵌入缓存** | 自动 | LRU 缓存 500 条，减少 API 调用 |

## 检索模式

### 上下文连续检索
对话历史自动融入后续查询。例如：

```
用户: "Redis 超时怎么办"
  → 系统检索: "Redis 超时怎么办"
  → 返回: [Redis 连接超时案例]

用户: "那个 ChannelHandler 的报错"
  → 系统改写: "Redis ChannelHandler 超时报错原因"  ← 融入历史
  → 返回: [更精确匹配]
```

### 全新独立检索
每次检索彼此独立，历史不传递。适合每次故障完全不同的场景。

## 防幻觉设计

系统采用**严格防御模式**：
- 检索无结果时，LLM **完全被绕过**，直接提示「未找到相关记录」
- 检索有结果时，LLM 仅基于检索到的内部参考资料作答
- 严格禁止 LLM 使用公开网络常识进行脑补或捏造
